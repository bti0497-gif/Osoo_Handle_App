# 일지 날씨·기온 사전 검토

2026-09-09 / 현장관리자용 앱 담당. 소스와 합성 입력으로 검토했으며 현장 실측 비교 및 운영 DB 좌표 검증은 미실시. 수정 구현 전 검토 기록이다.

## 확인된 동작과 위험

1. `weatherHistoryService.cjs`는 sites.target_lat/target_lng를 읽지만, 우선 공급자인 `kmaLandForecastService.cjs`에는 siteName/date만 전달한다. 기상청 지역은 `kma-land-forecast-regions.json` 이름별 고정 매핑이다. **기상청 주 경로는 처리장 좌표 격자로 조회하지 않는다.** 좌표는 Open-Meteo 대체 경로에서 사용한다.
2. 매핑에 청주휴게소(서울방향)→천안이 들어 있다. 이것이 잘못인지 실제 처리장 좌표/예보구역 경계를 대조해야 하며, 이름이 청주라는 이유만으로 청주 코드로 교체해서도 안 된다. 동명 양방향은 칠곡, 횡성 양방향은 횡성으로 동일 매핑되어 있다.
3. 기상청 응답에서 선택된 발표의 유효 기온 행들을 단순 평균하여 averageTemperature로 반환한다. 시간 구간 길이·표본 중복·24시간 완전성은 검증하지 않는다. 처리장 실측 일평균이나 24시간 평균이라고 보장할 수 없다. 더 최신 발표가 있어도 2개 이상 시간대가 있는 이전 발표를 먼저 선택할 수 있다.
4. 대체 공급자는 temperature_2m_mean(일 단위 평균)을 요청한다. 두 공급자의 평균 정의가 일치하는지 검토해야 한다. 현재 공급자가 바뀌어도 동일 기온 필드에 들어간다.
5. 날짜별 날씨는 강수/흐림 우선으로 요약한다. 잠깐 비가 예상된 날도 비로 표시될 수 있어 현장에서 보는 현재 날씨와 다를 수 있다. Open-Meteo의 daily weather_code 역시 하루 중 가장 심한 날씨를 뜻한다.
6. 캐시는 fetchedAt을 기록하지만 만료 검사 없이 재사용한다. 처음 조회한 예보가 같은 날짜 내내 고정될 수 있다. 임시 조회 캐시와 저장된 일지 스냅샷을 분리해야 한다.
7. 결측 기온에 Number('')/Number(null)을 적용하면 0이 된다. 기상청 합성 CSV의 빈 기온을 넣으면 0도로 요약되는 것을 확인했다. Open-Meteo 파서도 null 기온/코드를 0으로 바꿀 수 있어 결측값이 ‘0도/맑음’으로 나타날 위험이 있다.
8. 좌표가 없으면 휴게소명 검색의 첫 결과를 캐시한다. 처리장 좌표와 동일하다는 보장이 없다. 좌표 출처와 검증 여부 표시가 필요하다.
9. 현재 코드는 과거 날짜에도 Open-Meteo 대체 조회를 시도한다. 대화에서 합의했던 과거 조회 범위와 실제 실행 코드가 일치하는지 확인해야 한다. 이 검토를 근거로 자동으로 과거 정책을 변경하지 않는다.
10. HWP 생성 서비스도 buildHwpxBookmarkValues를 사용하므로 해당 함수의 날씨 바인딩은 HWP 출력에도 관련된다. HWPX 전용 문제로 보지 않는다.

## 제안하는 처리 기준

### 사용자 확정: 하루 대표 날씨 (2026-09-09)

- 일지의 날씨는 **해당 업무일(KST) 하루 중 가장 심한 날씨**를 대표값으로 사용한다. 잠깐 비/눈이 있었거나 예보되어도 맑음보다 해당 강수·악천후 상태를 우선한다.
- 오늘 하루가 끝나기 전에 작성하면 확보된 하루 예보를 기준으로 하며, 확정 관측 결과와 구분하여 출처를 보존한다. 하루 자료가 일부뿐이면 완전한 하루 결과인 것처럼 표시하지 않는다.
- 공급자의 공식 하루 대표 코드가 이 기준을 지원하면 재사용한다. 시간별 자료를 직접 집계할 경우 명시적인 우선순위 표를 사용하며 코드 숫자의 크기로 심각도를 판단하지 않는다. 현재 기상청 코드의 비/눈 등 우선순위가 이 정책을 충족하는지는 후속 구현에서 확인한다.
- 저장된 일지의 대표 날씨는 이후 예보 갱신으로 자동 변경하지 않는다.
- 이 결정은 **날씨 대표값**에 관한 것이며, 기온을 최고/최저값으로 변경하거나 평균 정의를 확정한 것은 아니다.

- ‘위치에 맞는 평균’을 인근 휴게소/관측소 좌표의 단순 평균으로 해석하지 않는다. 처리장 검증 좌표를 기준으로 자료 지점/격자를 선택하고, 기온의 시간 평균 정의를 별도로 정한다.
- 기상청 좌표 기반 자료로 전환할 때 지원 API·격자 변환·기온 변수·이용 권한을 공식 문서와 실제 응답으로 확인한다. 지역 육상예보의 TA를 24시간 관측 평균이라고 단정하지 않는다.
- 오늘 오전에는 오늘 하루의 확정 관측 일평균이 존재할 수 없으므로 예보 평균/현재 관측/누적 관측 평균 중 무엇을 표기할지 구분한다. 기존 양식의 ‘기온’ 칸 의미와 사용자 업무 기준에 맞춰 확정한다.
- 단위 °C, KST 기준일·시간 구간, 관측/예보 구분, 평균 산식과 표본 수를 명시한다. 소수점 자릿수는 최종 출력 때 처리한다.
- 결측은 null 유지, 가짜 0도/맑음 금지. 예보 실패와 좌표 없음은 별도 진단 결과로 기록한다.
- 최신 예보 조회 캐시는 만료/발표 시각으로 갱신하되 저장된 과거 일지의 날씨는 자동 변경하지 않는다.
- 미리보기에서 출처·기준시각·자동값 여부를 확인하고 현장 확인값으로 수정할 수 있는 UX를 후속 제안한다. 수정값과 원래 자동값·사유를 함께 보존한다.

## 일지 스키마에 필요한 날씨 스냅샷

점검 항목별로 기온을 반복 저장하지 않는다. 일지 개정에 종속된 1개 스냅샷 또는 별도 report weather 테이블을 권장한다. 점검 개정 테이블을 일지 전체 개정으로 확장할지, 일지 개정이 점검 개정을 참조하도록 할지는 구현 전에 결정한다.

필드 후보: site_id, work_date, report_revision_id, latitude, longitude, location_source, provider, product, region_id 또는 grid_x/grid_y, issued_at, fetched_at, valid_from/valid_to, timezone, temperature_kind, temperature_c, sample_count, aggregation_rule, weather_code/text, source(auto/manual), original_auto_value, override_reason.

이 스냅샷은 일지 생성 시 사용한 근거 보존 목적이며, 모든 현장의 날씨를 매일 자동 수집하는 신규 기능을 뜻하지 않는다. 실측 위치와 예보 지점의 차이는 명시하며 정확한 현장 실측이라고 표시하지 않는다.

## 후속 검증

청주·동명·횡성의 처리장 좌표→선택 구역/격자 대조, 빈 기온/null/오류 응답, 날짜 경계(KST), 발표 갱신, 공급자 전환, 시간대 중복/부분 자료, 저장 후 재출력 값 보존, 양방향 좌표 분리, 첫째·둘째 페이지/HWP 값 일치.

공식 참고: [Open-Meteo Forecast 문서](https://open-meteo.com/en/docs) — daily 집계 정의와 weather_code 의미. 기상청 현재 육상예보 TA의 구간별 의미와 대체 격자 API 계약은 공식 상세 문서 추가 확인이 필요하다. 이번 검토는 운영 인증키로 외부 조회하지 않았다.
