## 1. 사용자 동선

- 장비 상세 카드의 `+ 이력 추가` 버튼 왼쪽 또는 오른쪽 같은 버튼 묶음에 `엑셀 내보내기`를 둔다.

## 3. 구현 전에 양식 또는 스키마에서 보완할 사항

1. 양식의 `제원` 입력부 `A8:L16`에는 정의된 셀이름이 없다. `제원` 이름을 추가하는 것을 권장한다.
2. 상단의 `작성일`, `제정일자`, `설비관리자`, `문서 번호`, `설비 위치`, `page` 입력부도 이름이 없다. 실제 자동 입력 대상이면 각각 고유한 셀이름을 추가한다.
3. 현재 `equipment_assets`에는 구매가격과 설비등급 전용 컬럼이 없다. 구매가격을 이력 비용이나 다른 필드에서 추정하지 않는다. Phase 2 스키마 확정 시 `purchase_price`, `equipment_grade` 추가 여부를 결정한다.
4. `설비등급`에 `category3`(기계/전기/계측기)을 임의로 넣지 않는다. 분류와 등급은 다른 값이다.
5. 기존 `parseNamedRanges()`는 단일 셀 정의만 해석한다. `날짜`, `수리내역`, `금액`, `업체명`처럼 범위로 정의된 이름은 별도의 범위 파서가 필요하다.

## 4. 이력 행 바인딩 계약

- 이력은 날짜 오름차순으로 정렬하고 같은 날짜에서는 `id` 또는 `created_at` 순서를 고정한다.
- 19행부터 한 이력당 한 행씩 기록한다.
- `date`는 Excel 날짜 값으로 기록하고 표시 형식은 양식의 기존 형식을 보존한다.
- `price`는 숫자로 기록하며 빈 값과 0원을 구분한다.
- `company`가 없으면 빈 셀로 유지한다.
- `수리내역`은 `type`과 `content`를 합치되, 중복 문구를 만들지 않는 포맷 함수를 한 곳에서 관리한다.
- 사용하지 않는 나머지 행은 양식의 예시값이 남지 않도록 값만 비운다. 스타일·병합·행 높이는 유지한다.
- 46건을 초과하면 자르지 않는다. 같은 양식 시트를 복제하여 `1`, `2`, `3`으로 페이지를 추가하고 장비 기본정보를 각 시트에 반복한다.

## 5. 권장 구현 구조

### 프론트엔드

- `EquipmentModel.exportEquipmentCard(equipmentId)`만 API를 호출한다.
- ViewModel은 선택 장비, 생성 중 상태, 성공/실패 안내를 관리한다.
- View는 `+ 이력 추가` 옆에 버튼만 렌더링한다.
- 브라우저 임의 다운로드 대신 기존 Electron 저장/열기 흐름을 재사용한다.

### 백엔드

- 라우트는 요청 검증과 응답만 담당한다.
- Excel 로직은 `server/services/equipmentCardExcelService.cjs`로 분리한다.
- 기존 `excelOpenService.cjs`의 병합 범위·이미지 삽입·파일 열기 기능을 재사용한다.
- 출력 데이터는 Excel 처리 전에 `{ equipment, history, photo }` 스냅샷으로 확정하고 필수 키를 검증한다.
- 장비와 이력은 반드시 동일한 `site_id`로 다시 조회한다. 클라이언트가 보낸 장비명이나 현장명을 신뢰하지 않는다.
- 양식은 구현 시 `templates/reports/설비이력카드.xlsx`로 편입하고 패키징·기존 양식 보호 계약에 포함한다.

## 6. 출력 파일 정책 제안

- 파일명: `설비이력카드_<관리번호>_<설비명>_<YYYYMMDD>.xlsx`
- Windows 파일명 금지문자는 `_`로 치환한다.
- 같은 파일이 있으면 덮어쓰지 않고 `(2)`, `(3)`을 붙인다.
- 기본 보관 위치는 구현 전에 사용자와 확정한다. 후보는 바탕화면 `장비이력카드모음`이다.

## 7. 회귀검증

- 다른 현장의 같은 관리번호 장비가 섞이지 않는다.
- 숨김 장비도 명시적으로 선택했다면 기존 이력과 함께 출력된다.
- 이력 0건, 1건, 46건, 47건을 각각 검증한다.
- 대표사진 없음/있음, 긴 수리내역, 업체명 없음, 금액 0/공란을 검증한다.
- 원본 양식 SHA256이 생성 전후 동일하다.
- 출력 파일을 다시 열어 정의된 이름의 값과 이력 건수를 검증한다.
- 이미지가 셀 경계를 침범하지 않고 A4 가로 인쇄가 유지되는지 확인한다.
- 진단러너에 `equipment-card-excel` 시나리오를 추가하고 릴리즈 전 `validate`와 패키지 양식 포함 여부를 확인한다.

## 8. 현재 결론

셀이름 덕분에 기본정보와 이력 바인딩은 안정적으로 구현할 수 있다. 다만 범위형 셀이름 파서, `제원` 이름, 구매가격·설비등급 데이터 출처, 46건 초과 페이지 정책을 먼저 확정해야 실제 구현에서 위치 추측이나 잘못된 값 대입을 피할 수 있다.
