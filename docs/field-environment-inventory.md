# 현장 환경 인벤토리

32 안정화 버전부터 수집하는 `electron / environment-baseline / observed` 진단 이벤트를 현장별로 정리하는 관리 문서다. 이 문서는 운영 코드의 설정값이 아니며, 진단로그를 분석한 뒤에만 갱신한다.

## 수집 원칙

- 패키지 앱이 서버 준비 상태에 도달한 뒤 앱 버전당 현장 PC별 1회만 기록한다.
- 기존 30분 진단 묶음 전송에 포함되며, 업무 화면·로그인·동기화 요청에는 개입하지 않는다.
- 비밀번호, 토큰, 인증서, API 키, 사용자 이름, 전체 파일 경로, 현장 DB 내용은 수집하지 않는다.
- 환경값이 없거나 읽기 실패해도 앱은 정상적으로 계속 실행한다.

## 진단 이벤트에서 확인할 항목

- 앱/런타임: 앱 버전, Electron·Chrome·Node 버전, 설치 범주
- 운영체제: Windows 버전·커널·아키텍처
- 자원: 시스템 메모리, AppData가 있는 디스크의 전체/여유 공간
- 로컬 실행 기반: SQLite 파일 존재, 서버 준비 상태
- 감시런처: 패키지 포함 여부, 최근 상태 파일의 버전·상태·확인 시각·유지보수 사유

## 2026년 10월 15일 현장별 전환 호환성 기준표

기존 수집자료를 기준으로 작성했다. 런타임·배포 방식은 아직 확정되지 않았으므로 아래 판정은 .NET 설치 합격 판정이 아니라 전환 준비 상태다. 2027년 약 10개 현장 추가 전에 전환을 완료하는 것이 사용자 일정 조건이다. 신규 현장은 도입 전에 같은 환경 계약을 확인한다.

### 환경 기준선이 확인된 현장

메모리는 OS가 보고한 사용 가능 총량(GiB)으로 설치 용량보다 작게 표시될 수 있다. 디스크 여유는 환경 기준선 수집 당시 AppData가 위치한 볼륨 값이며 현재 여유나 디스크 종류를 뜻하지 않는다. 날짜는 KST다. 각 현장의 가장 최근 environment-baseline 이벤트를 사용했다.

| --- | --- | ---: | ---: | --- | --- | --- |

9개 기준선 모두 x64 패키지·machine-program-files 설치·서버 준비 성공·패키지 런처 포함이 확인됐다. 런처의 maintenance/update 또는 server-starting 상태는 수집 순간의 상태이며 그것만으로 장애 판정하지 않는다. Windows 명칭은 빌드로 분류했으며 에디션·ESU 가입·정식/시험 채널은 수집되지 않아 지원 상태를 단정하지 않는다.

### 일부 정보만 확인된 현장

| 현장 | 확인된 내용 | 근거 시점 KST | 남은 확인 |
| --- | --- | --- | --- |
| 외동 포항 | 사용자 확인 Windows 7 사용, 로그 앱 버전 1.1.8-win7.1 | 사용자 설명 및 2026-10-12 로그 | SP1·OS 비트수·메모리·디스크·필수 구성요소. win7-ia32 배포 기록만으로 OS 자체가 32비트라고 단정하지 않음 |
| 안동 부산 | OS 보고 총 메모리 약 7.9GiB, 앱 1.1.53 | 2026-10-14 | Windows 빌드·비트수·디스크·CPU |
| 청주 서울 | OS 보고 총 메모리 약 15.8GiB, 앱 1.1.53 | 2026-10-14 | Windows 빌드·비트수·디스크·CPU |
| 동명 부산 | 해당 site_id의 앱 1.1.53 기록 존재 | 2026-10-14 | 실제 PC와 동명 춘천 PC의 공유 여부 및 환경 기준선 |

양방향 창의 작업 로그가 한 PC에서 전송될 수 있으므로 site_id는 PC 고유 식별자가 아니다. 동명 부산·죽암 서울 등 반대 방향에 같은 PC 사양을 임의 복사하지 않는다. 최신 로그가 없다는 것만으로 미설치·미업데이트라고 단정하지 않는다.

### 로컬 등록 목록에는 있으나 환경 자료가 확인되지 않은 현장

읽기 전용으로 확인한 로컬 sites의 is_active=1 목록 기준이다. 등록 상태는 실제 운영·앱 사용 여부의 확정 근거가 아니다. 기존 중앙 자료나 과거 원본에서 먼저 보완하고, 남는 항목만 현장에 확인한다.

| 금왕 평택 | 환경 자료 미확인 |

| 선산 양평 | 환경 자료 미확인 |

개발용 등록 현장 '오수처리장'은 운영 현장 판정에서 제외한다. 총 등록 26개 중 이를 제외한 25개를 기준선 9개·일부 확인 4개·미확인 12개로 구분했다. 2027년 추가 예정 현장 약 10개는 명칭과 장비가 미확정이므로 이 표에 임의 생성하지 않는다.

### 기술 선택 전 필수 결정

1. 외동 Windows 7을 동일 신버전의 지원 범위에 포함할지 사용자와 확정한다. PC 교체를 기정사실로 삼지 않는다. 포함 시 구형 런타임·브라우저·32비트 배포 유지 비용을 별도로 검토한다.
2. 현대 .NET과 .NET Framework는 별개다. Windows 7 SP1의 .NET Framework 4.8 설치 가능 여부와 현대 .NET의 지원 여부를 혼동하지 않는다. 자체 포함 배포도 OS 지원 제한을 없애지 않는다.
3. WinForms 화면뿐 아니라 Node 백엔드(재사용 시), SQLite 네이티브 DLL, 내장 브라우저, HWP COM·Excel 및 Office 비트수, 감시런처, 설치·자동업데이트 전체 조합을 검증한다. 현재 자료에는 CPU 모델·명령어셋·Office/HWP 상세 버전이 없으므로 추정하지 않는다.
4. 기존 AppData·설정·DB·사진·양식을 보존하고 OS·아키텍처별 설치/업데이트/롤백을 실기 시험한다. 부적합 설치본은 배포 단계에서 구분하고 설치 전에 설명과 함께 차단한다.
5. 신규 현장 확대 전에 대표 환경별 파일럿과 운영 인수를 완료한다. 정확한 완료일·최소 지원 Windows·최소 메모리는 PoC 결과와 현장 추가 시점 확정 후 결정하며, 아직 보장된 일정으로 표시하지 않는다.

### 출처와 갱신 방법

- 중앙관리자 전용 diagnostics.db / drive_diagnostic_events의 environment-baseline, memory-pressure, slow-api-request 및 현장별 최신 로그. 기준 조회일 2026-10-15.
- 로컬 앱 `osoo.db` / sites: 활성 등록 목록만 읽었으며 업무 DB는 변경하지 않았다.
- 사용자 제공 외동 Windows 7 사용 정보, 과거 횡성 강릉 메모리 모델·4GB 확인 내용. 과거 대화의 하드웨어 모델을 다른 현장에 적용하지 않는다.
- [현대 .NET Windows 설치 및 지원 기준](https://learn.microsoft.com/dotnet/core/install/windows), [.NET Framework 4.8 설치 대상](https://support.microsoft.com/en-us/servicing/dotnetframework/2019/10/microsoft-net-framework-4-8-offline-installer-for-windows).
- 다음 갱신은 site_id별 최신 환경 기준선과 실제 PC 공유 관계를 대조한다. 자격증명·사용자 이름·전체 로컬 경로는 표에 넣지 않는다.

## 판정 기준

- **환경 확인됨**: OS·아키텍처·자원 기준선이 있음. 이것만으로 .NET 설치·지원 합격을 뜻하지 않는다.
- **확인 필요**: 감시런처 상태 파일 부재, 디스크 여유 부족, 설치 범주가 예상과 다름.
- **선행 조치 필요**: 서버 준비 실패 반복, 감시런처 미포함/구버전, 운영체제 또는 아키텍처가 2.x 요구사항과 맞지 않음.

2.x 실제 요구사항과 임계값은 WinForms PoC와 배포 방식이 확정된 뒤 이 문서에 추가한다. 현재는 현장 환경의 기준선을 수집·비교하는 용도만 가진다.
