# 현장 앱 로컬 우선·백그라운드 라우트 정책

## 절대 원칙

1. 현장 로그인은 로컬 회원 캐시 검증만으로 완료한다.
2. 유량·수질·약품·키트·운전상태·출결·사진은 로컬 DB와 로컬 파일에 먼저 저장한다.
3. 일반 업무 화면은 Google Drive, BigQuery, Google Sheets 응답을 기다리지 않는다.
4. 자동 원격 작업은 마지막 키보드·마우스 입력 후 30분이 지나야 시작한다.
5. 실행 중 입력이 감지되면 현재 원격 요청까지만 마치고 다음 작업 전에 중단한다.
6. 앱이 종료되어도 재개할 수 있도록 원격 작업을 실행 전에 영구 TODO로 기록한다.
7. 서버 재시작 시 `running` 작업은 `pending`으로 복원한다.

## 영구 작업 원본

- 운영 데이터: 각 테이블의 `is_synced=0`
- 작업 순서와 재시도 상태: `background_tasks`
- Drive 파일 전송: `background_file_tasks`
- 진단로그: `app_diagnostic_logs`의 미전송 행

허용 작업 이름은 다음 7개로 고정한다.

- `attendance-sync`
- `data-sync`
- `file-sync`
- `certificate-cache`
- `board-cache`
- `diagnostic-sync`
- `update-check`

서버는 이 허용 목록 밖의 작업 준비·claim·완료·실패 요청을 거부한다.

## 자동 작업과 명시적 작업의 경계

자동 작업은 위 유휴 큐만 실행한다. 게시판 팝업은 서버를 조회하지 않고 유휴 작업이 갱신한 메모리 캐시만 읽는다. 진단로그 업로드와 업데이트 확인도 같은 큐에 속한다.

다음은 사용자가 해당 기능을 직접 요청한 명시적 원격 작업이므로 즉시 실행할 수 있다.

- 소통게시판 메뉴에서 목록 읽기, 글·댓글·첨부파일 처리
- 관리자 설정의 Google Sheets 조회·수정
- BigQuery 복원·점검 버튼
- QnTECH 원본 자료 가져오기
- Drive 파일 직접 다운로드·복원
- 로그인 로컬 캐시가 없을 때의 관리자/복구용 원격 회원 조회

명시적 기능에서 원격 오류가 발생해도 앱 전체 로그아웃이나 로컬 업무 중단으로 전파하지 않는다.

## 검증

`npm run validate:background-policy`는 다음 회귀를 차단한다.

- 사진 저장 라우트의 직접 Drive 업로드
- 로그인 직후 업데이트·BigQuery·게시판 자동 조회
- 진단로그의 독립 타이머 업로드
- 게시판 팝업의 독립 폴링
- 30분 유휴 및 사용자 입력 중단 계약 제거
- 허용 목록 없는 임의 백그라운드 작업
- 영구 파일 큐와 중복 방지 계약 제거
